Found while validating fix-swap-boundary. The stress-harness test tests/glitch_stress_harness.rs::test_seeded_session_60s_50_swaps_zero_false_positives asserts a callback-budget overrun fraction (budget_overrun_block_fraction = 0.20) computed from WALL-CLOCK render time (Instant::now() in run_random_session, src/stress_harness.rs) vs a real-time deadline (block_frames/sample_rate ≈ 11.6 ms).

Under cargo test (which runs ~150 test binaries in parallel) AND on a shared box under high load (observed load avg ~78 from concurrent agents), p50 render time balloons from ~840 µs to 7–11 ms and the test FALSELY reports "callback-budget overruns: 30–49% of blocks over budget". It passes cleanly when the harness binary is run in isolation (12/12) and standalone (glitch_stress --seed 42 → 0.3% overrun). This is a false positive: a real-time deadline asserted inside a non-real-time, oversubscribed test runner.

Goal: keep the detector meaningful for the standalone/CI real-time check but stop it from false-failing under test-runner contention. Options to weigh:

  • Gate the wall-clock budget assertion behind an env flag / --release real-time mode, off by default in cargo test.
  • Normalize render cost to a work metric (e.g. samples processed per unit CPU) instead of raw wall-clock, or calibrate the deadline against a measured single-block baseline taken at test start.
  • Detect contention (baseline probe) and SKIP (loud) rather than FAIL when the machine is oversubscribed.

Implement directly — do not decompose further.

Description

Addresses C2 (rt F-2) and C3 (rt F-3): render-thread panics and priority inversion.

  • C3 / F-3: Sample&Hold stores per-node scalar state as Mutex<f32> locked 4× per sample with .unwrap() (src/unified_graph.rs:14023-14033); fundsp state (:13788,13834,13872) is likewise .unwrap()-locked on the hot path. A poisoned lock (from any panic) → render-thread panic; per-node scalar state does not need a mutex at all.
  • C2 / F-2: the plugin branch (src/unified_graph.rs:12122-12208) does real_plugins.lock().unwrap() (×3-4), loads+initialises a VST3 from disk on first render, and allocates a Vec<(String,f32)> of cloned param names every sample; fundsp path (:13788-13882) locks + may recreate the unit on param change.

See docs/audits/rt-safety-2026-07.md §4 F-2/F-3 and docs/audits/improvement-plan-2026-07.md C2/C3.

Scope / Constraints

  • Files: src/unified_graph.rs only (+ tests). This is the HEAD of the serial unified_graph.rs chain; it is --after the three in-flight tasks (fix-swap-boundary, complete-fx-state, investigate-u1-swapping) to avoid a multi-way conflict on this file.
  • Replace per-node Mutex<f32> state (Sample&Hold, etc.) with plain fields (the graph is single-writer under the render borrow).
  • Plugin path: instantiate/initialise plugins at compile/reload (never on the render thread); reuse a scratch param Vec across samples; try_lock with silence fallback; ban .lock().unwrap() on the render path.
  • The GlobalClock .lock().unwrap() in phonon-audio.rs:269 is out of scope here (that file is owned by fix-synth-borrow-race); note it for a follow-up if not handled there.
  • Implement directly — do not decompose further.

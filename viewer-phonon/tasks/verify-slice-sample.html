Description

Found while working on triage-fix-pre. slice n indices on a multi-sample pattern like s "bd sn hh cp" plays sub-SLICES of each sample buffer (begin/end fractions), so with indices like "3 2 1 0" the first half of the cycle renders near-silent (decay-tail slices) while attack slices are loud. This is Tidal-ish sample-slicing behaviour, but for a pattern where each slice window already contains a full discrete sample it is arguably wrong (should reorder full samples). The level-2/3 audio tests in tests/test_slice_pattern.rs were relaxed to assert non-silence + audible band instead of energy/count preservation.

Decide the correct semantics: (a) sample-buffer slicing (current), or (b) full-sample reorder when each window holds one discrete sample; then tighten the tests accordingly.

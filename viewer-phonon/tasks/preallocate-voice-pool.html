Description

Addresses G4 (rt-safety audit F-4). When all voices are active, a new trigger calls grow_voice_pool (src/voice_manager.rs:905-955, from allocate_voice :1044), which self.voices.push(Voice::new()) in a loop (heap alloc + full-vector realloc/memcpy of a large per-voice struct) and eprintln!s the growth — all on the synth thread, exactly when the engine is already overloaded → render-time spike + stderr backpressure → underrun.

See docs/audits/rt-safety-2026-07.md §4 F-4 and docs/audits/improvement-plan-2026-07.md G4.

Scope / Constraints

  • Files: src/voice_manager.rs only (+ a test file). No src/unified_graph.rs edits.
  • Pre-grow the pool to a configured ceiling at compile/reload (off the synth thread); on exhaustion steal without allocating (oldest-voice stealing already exists at :98).
  • Remove/defer the eprintln! from the hot path — count growth/steal events atomically and report off-thread.
  • Keep ABSOLUTE_MAX_VOICES semantics intact.
  • Implement directly — do not decompose further.

Reproduction (interactive → stress harness)

Dense sample patterns (s "bd*16" layered, long tails, no cut groups) exhaust the 256 initial pool during live play. Add a stress-harness scenario (dense-trigger session) that would spike render time / underrun under pool growth on main.

Validation

  • Failing test first: a regression asserting that steady-state dense triggering does no heap growth on the synth thread (e.g. voice count reaches ceiling then stays; allocation / growth counter stays 0 during rendering) and produces no per-buffer render-time spike / simulated underrun via the stress-harness budget detector.
  • Fix: pre-grow at compile/reload; steal without alloc on exhaustion; no synth-thread eprintln!.
  • Post-fix: the dense-trigger stress scenario is clean (no underrun/budget overrun attributable to voice growth); cargo run --release --bin glitch_stress -- --seed 42 still exits 0.
  • cargo build + cargo test pass with no regressions.

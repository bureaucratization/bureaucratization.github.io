Description

Description

Addresses G6 (pattern-timing audit F6). For any inline Signal::Pattern, the mini-notation string is parsed from scratch on every sample (src/unified_graph.rs:10181-10193) — ~44,100 parse_mini_notation + allocate cycles per second per such signal. This is a real-time-safety violation (allocation on the synth thread) and a large CPU cost that directly raises underrun probability → the timing glitches of pt-F1. SignalNode::Pattern already avoids this via the event cache; the inline branch does not.

See docs/audits/pattern-timing-2026-07.md §8 F6 and docs/audits/improvement-plan-2026-07.md G6.

Scope / Constraints

  • Files: src/unified_graph.rs (+ src/compositional_compiler.rs if the parse must move to compile time) + tests. Serial chain: --after sanitize-node-state (shares unified_graph.rs).
  • Parse the mini-notation ONCE at graph-compile time and store the Pattern<String> (as SignalNode::Pattern does), or memoize parse_mini_notation keyed by string. No parsing may occur in eval_signal_at_time / the per-sample path.
  • Preserve exact onset timing and event semantics — this is a caching/lifetime change, not a behaviour change.
  • Implement directly — do not decompose further.

Reproduction (interactive → stress harness)

A patch with an inline Signal::Pattern used as a control incurs a per-sample parse. A budget / allocation regression through the stress harness shows the render-time cost on main.

Validation

  • Failing test first: a regression asserting eval_signal_at_time performs zero mini-notation parses per sample for an inline Signal::Pattern (parse-count instrument or allocation counter), and/or a stress-harness budget scenario showing the per-sample-parse render cost pre-fix.
  • Fix: compile-time parse / memoization; identical pattern query results.
  • Post-fix: parse happens once; onset timing unchanged (Level-1 query + Level-2 onset tests pass); cargo run --release --bin glitch_stress -- --seed 42 exits 0.
  • cargo build + cargo test pass with no regressions.

Description

Found while working on fix-pre-existing-5. The default CLI render path (src/main.rs, realtime=true parallel=true) splits the timeline into 512-sample blocks, clones the graph per rayon thread, and calls seek_to_sample() before each block. Sample VOICES do not survive across these boundaries: only the very first hit of the render plays its full ~4467-sample body; every subsequent hit is truncated.

Repro: printf 'tempo: 0.5\n\nout $ s "bd*4"\n' > /tmp/t.phonon phonon render /tmp/t.phonon /tmp/t.wav --duration 2

h0@0 plays full (~4400 samples); h1@22050 ~504, h2@44100 ~982, h3@66150 ~1428

each truncates exactly at the next rayon thread-chunk boundary (block 44/88/132 for 16 threads)

Two distinct truncation causes observed:

  1. Thread-chunk boundary: a voice triggered near the end of one thread's block range plays only to that range end; the next thread's clone (seeked to its own start cycle, last_trigger_time init just before it) never triggered that still-sounding voice, so it renders silence.
  2. Even with --threads 1 (single chunk), a cross-CYCLE hit (cycle position 0.0 of cycle N>0) truncates to ~130 samples mid-block. Root cause not fully isolated; likely in the seek/cached_cycle_position + voice_buffers vs voice_output_cache (newly_triggered_voices) interaction in process_buffer_dag / eval_node_buffer_dag (src/unified_graph.rs ~7399, ~7990-8098).

graph.render() (sequential, no seek) does NOT truncate -- test_house_beat_pattern_timing renders 8 cycles cleanly. So this is specific to the seek/parallel CLI path. It does not fail the current test suite (onsets still fire on the attack transient) but it is a real audio-quality defect: multi-cycle sample patterns rendered via CLI lose the tail of every hit after the first.

Validation

  • Failing test written first (render s "bd*4" or s "bd" multi-cycle via CLI parallel path; assert each hit's nonzero span ~= full sample length, not truncated at chunk/cycle boundaries)
  • Voices triggered in one block/thread-chunk continue rendering into subsequent blocks/chunks (catch-up trigger on downstream clones, or overlap-render, or render voices continuously)
  • Sequential graph.render() output unchanged; parallel output matches sequential within tolerance
  • cargo build + cargo test pass with no regressions

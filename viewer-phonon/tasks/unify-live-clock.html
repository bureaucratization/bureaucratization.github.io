Description

Addresses T1 (pattern-timing audit F1 + F2), the marquee timing fix.

  • pt-F1: the live clock is re-anchored to wall-clock at render time every buffer (src/unified_graph.rs:18001, via src/live.rs:108 and src/main.rs:1006 calling process_buffer()), not advanced by samples emitted. Because the synth thread renders ahead into the ring, buffer_start_cycle collapses to a tiny overlapping band → startup / post-underrun onset clustering + steady-state onset jitter tied to callback cadence.
  • pt-F2: set_cps() (src/unified_graph.rs:5060) changes tempo with no offset compensation → in wall-clock mode the cycle position teleports by elapsed·Δcps (an hour in, cps 2.0→2.5 jumps ~1800 cycles).

The correct model already exists: GlobalClock in src/bin/phonon-audio.rs:98 advances by sample count and rebases on wall-clock only at tempo changes (get_buffer_timing :155, set_cps :135). Route live rendering through process_buffer_at() (unified_graph.rs:17982); the doc comment at :17997 already says to.

See docs/audits/pattern-timing-2026-07.md §3 F1, §4 F2, §14 and docs/audits/improvement-plan-2026-07.md T1.

Scope / Constraints

  • Files: src/unified_graph.rs (clock methods, set_cps), src/main.rs (live loop → process_buffer_at + shared clock), src/live.rs (migrate off process_buffer). Serial chain: --after dag-scratch-arena (shares unified_graph.rs) AND --after fix-synth-borrow-race (shares main.rs).
  • Advance the clock by samples emitted; consult wall-clock only to rebase (startup / explicit resync / post-underrun). Make UnifiedSignalGraph::set_cps rebase exactly like GlobalClock::set_cps (capture position, reset origin, then change cps).
  • Preserve the reload-path cycle continuity that already works (transfer_session_timing); do not regress §12/§13 SAFE behaviours (setCycle/nudge/resetCycles/reload cps change).
  • Do NOT attempt the render-owner threading rewrite here (deferred, plan §5) — this is the clock/ timing-source unification only.
  • Implement directly — do not decompose further.

Reproduction (interactive → stress harness, onset timing)

Startup onset clustering and a set_cps teleport are both observable via onset detection. Add stress-harness / onset-detection scenarios: (a) first ~1 s of output has correctly-spaced, non-clustered onsets; (b) a live set_cps keeps cycle position continuous (no jump).

Validation

  • Failing test first: (a) an onset-timing regression showing startup/post-burst onset clustering on main (onsets bunched vs the sample grid); (b) a set_cps-on-running- graph test showing a cycle-position teleport on main.
  • Fix: sample-advancing clock via process_buffer_at; rebasing set_cps.
  • Post-fix: onsets are sample-grid-spaced with no startup clustering; set_cps position is continuous (jump ≈ 0); reload/setCycle/nudge continuity preserved; cargo run --release --bin glitch_stress -- --seed 42 exits 0.
  • cargo build + cargo test pass with no regressions.

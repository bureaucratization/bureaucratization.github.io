completion-event-wakeups

Completion-event wakeups for the pi plugin: the pi chat session should be told when tasks finish instead of having to ask 'check the graph state'. Today the plugin (worksgood-pi/) shells out to wg on demand and the only push surfaces are wg msg/chat-inbox (daemon-side, not delivered to a live pi session) and the new viz panel (a view, not a wake). Deliverables: (1) DESIGN: docs/design-pi-completion-wakeups.md covering the event taxonomy (terminal transitions: done/failed/blocked/waiting-on-human; which tasks matter: top-level/no-parent tasks and any failure, versus every task), the wake primitive on the pi side (pi.sendMessage to inject a session message the agent sees and can act on, ctx.ui.notify for a lightweight ping) and its honest limit (a pi session is turn-based: the plugin can make the information present and visible; document whether/when it can trigger an actual turn), the subscription/dedup model (persisted cursor so a transition is announced once), multi-instance fan-out (several pi sessions attached to one daemon each keep their own cursor), and the config surface (plugin-side settings with safe defaults: failures always; completions top-level by default; per-session quiet toggle). (2) MINIMAL SLICE: implement the polling watcher first (interval read of graph state via the existing wg backend - no daemon protocol change needed), emitting a deduped wake message on qualifying transitions, configurable, with the daemon-push/event-stream path documented as the follow-up (the backend already notes the WG_DAEMON_SOCKET IPC client as future work). Message content must be actionable: task id, title, status, completion summary/receipt reference, and the note that wg tools are available for detail - never a bare 'something changed'. (3) Tests: unit tests for transition detection + dedup/cursor persistence + config gating (fake graph snapshots, no live daemon); one integration check against a real graph with a scratch pi session if feasible. Reuse: worksgood-pi/src/wg-backend.ts (exec host, WG_DAEMON_SOCKET note), viz-snapshot.ts/viz-readmodel.ts (graph reading), the existing plugin test setup. ## Validation - [ ] docs/design-pi-completion-wakeups.md committed with the taxonomy, wake primitive + its limit, dedup model, multi-instance story, config defaults - [ ] Minimal slice works: a task completing in a watched graph produces exactly one actionable wake message in the session; a repeated poll never re-announces it - [ ] Config gating verified (failures always; completions top-level by default; quiet toggle honored) - [ ] Plugin tests green; cargo test --lib green; fmt/clippy clean; worktree clean

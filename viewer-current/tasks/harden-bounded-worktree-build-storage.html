Description

The CoW build-storage implementation landed at 5cab9d2c/2b51fb84 but its bound FLIP review rejected it with five concrete safety/completeness findings. Close all findings before the new binary is installed or treated as production-ready. Do not weaken tests or dismiss the findings as advisory.

Required corrections:

  1. Cold baseline under-reservation: projection_for_class / build_admission_for_source currently charge and serialize a missing cold baseline only for BuildHeavy. Any BuildCapable worker can materialize Cargo output; reserve/serialize cold baseline creation for every build-capable class, while keeping private-delta class floors appropriate.
  2. Incomplete cache key inputs: compute_key relies on env hints not derived from the actual Cargo invocation. Define an honest namespace contract. Capture all build-affecting command inputs WG controls (profile/release, target triple, features/no-default/all-features, rustflags/config) or conservatively isolate/disable baseline reuse when exact command identity is unavailable. Never share an “exact” baseline across incompatible invocations.
  3. Rollback safety: construct ownership/creation guards immediately when paths are created. A TMPDIR failure must not strand an unregistered target. Drop may remove only a directory proven newly created by this attempt; never an existing directory.
  4. Absolute TMP isolation: project-key every configured absolute build_tmp_root before appending agent ID, so separate graphs with identical agent IDs cannot share scratch.
  5. Candidate-binary evidence: run the credential-free bounded_worktree_build_storage.sh using the freshly built candidate binary, not the globally installed old binary. Bind/report its result as deterministic evidence.

Also inspect the landed implementation for adjacent hard-link/reflink mutation safety and exact lease cleanup. Preserve dirty source/artifacts. Keep max build concurrency at one during this repair.

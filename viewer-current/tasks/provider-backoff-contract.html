Description

Objective

Replace the earlier broad provider-backoff proposal with the user-approved minimal V1 contract. Inspect and reuse retained work, but revise its scope rather than publishing the old design unchanged. Trace the CURRENT production dispatcher and completion authority; the deployed service uses direct fail-stop, NOT PlannerStore. Do not restore retired scheduling authority or add an LLM controller.

V1 automatically retries ONLY unambiguously classified transient SOURCE-provider failures: 429/rate limit, eligible temporary server/provider outage, and transport failure where execution state can be safely reconciled. Preserve the exact handler/model/route, partial work, failure evidence, and lifecycle/attempt/publication fences. Unknown or ambiguous execution outcomes require reconciliation or operator attention, never blind re-execution.

Use an explicit opt-in retry policy; disabled retains existing fail-stop semantics. Specify a small fixed default retry budget and total elapsed-time budget with a bounded deterministic delay schedule. Start with at most THREE automatic retries within a FIFTEEN-MINUTE recovery window (measured from first failure); justify any necessary compatibility adjustment with evidence. Retry-After is a lower bound: if it falls beyond the remaining window, request attention rather than retry early. Neither restart nor duplicate failure evidence resets the window or replenishes retries. Reset a failure episode only on explicit operator action or authoritative successful recovery, not incidental stream output.

Exhausted budgets become visibly NeedsAttention/recovery-exhausted with saved work, reason, attempts used, and one next action. They do not imply a semantic quality failure. Preserve existing manual pause/cancellation and completion dispositions. A maximum delay alone is NOT a retry budget.

Never auto-retry semantic/review rejection, invalid credentials/configuration/credit, completion-authority/integrity failures, or user-paused/cancelled work. Do not invoke an evaluator to rediscover a directly evidenced provider error. Reviewer/evaluator failures remain under existing policy; no new evaluator retry mechanism in V1.

Reuse existing dispatch ownership, route protections and persistence; no second scheduler or new elaborate probe subsystem. Ordinary status/show must disclose current recovery state, attempts remaining, next retry or needs-attention, and one actionable recovery instruction. Defer Agency learning/projection integration, evaluator-only retries, rich TUI/config controls, hour/day unattended backoff, and fleet-scale new breaker/probe architecture.

Validation

  • Maps actual production authority and gives a compact failure decision table including non-retryable and ambiguous outcomes.
  • Defines retry budget, elapsed window, delay, Retry-After interaction, pause/cancellation, restart persistence and narrowly authorized reset conditions.
  • Identifies exact attempt/evidence/deduplication fences preventing duplicate execution effects or publication.
  • Defines bounded visible exhaustion and one safe next action without false quality scoring.
  • Gives focused fake-clock/integration and real-entry-point smoke cases for the implementation; no demand for future self-review receipts.
  • Clearly lists deferred scope and current implementation seams so the next worker can ship without reopening architecture.
  • cargo fmt --check and git diff --check pass; attach executed evidence.

fix-local-pi-startup-control-resilience

Make local Pi startup authorization resilient and failure-neutral

Description

Make trusted local Pi worker startup resilient to worker-control IPC stalls, service overload/restart, and continuation bootstrap races. Motivating observed failure: e97-paper-corpus-receipt never began source work; worker-control IPC timed out after 30s, no watchdog state existed for the current attempt, worker_control.stale_capability was emitted, pi_process_epoch=0, and Pi exited without policy-valid continuation authorization. No worktree changes/commits or scientific jobs occurred, yet the source task was classified failed. Treat this as control-plane availability failure, not source execution failure.

Design startup as a recoverable transaction. Establish and durably bind the task generation/attempt/fence, process epoch, worker-control capability, launch intent, and Pi-watchdog/observer state in a coherent order before source execution can begin. Reconcile crashes after every boundary. A missing or delayed IPC acknowledgement must not leave an unobservable Pi process or an attempt that can neither continue nor retry.

For an ordinary trusted local worker, prefer a bounded lease-valid startup/continuation authorization that can survive a temporary coordinator IPC outage. The capability must be exact-task/attempt/fence/process bound, expiring, attributable, and locally verifiable; confirmed revocation, stale fence, or process-epoch mismatch still stops the worker. Do not require a live round trip for every continuation if a valid durable local lease exists. Observation-only, remote, or explicitly scoped/untrusted actors may remain fail-closed according to their mode. Coordinate this policy with restore-trust-first-local-worker-control rather than creating a second inconsistent trust system.

Correct lifecycle classification. If no policy-authorized model turn/source command began and no source mutation occurred, authorization timeout/stale-bootstrap/watchdog-creation failure is a typed neutral startup-deferred/infrastructure event: it creates no scientific/source failure, consumes no task retry/evaluation/FLIP/provider-health budget, and is retried automatically with bounded backoff when service health returns. If source execution did begin, preserve its exact attempt and recover worktree/session state rather than pretending it never ran. Never silently downgrade a confirmed stale/revoked capability.

Expose this state plainly in CLI/JSON/TUI: waiting for worker-control startup, bootstrap phase, attempt/process epoch, watchdog presence, retry/backoff, and whether any model/source execution occurred. Do not report a scientific/implementation failure when provenance proves execution never started.

Validation

  • Isolated fake-Pi fixture reproduces a >30s worker-control IPC stall and service stopping/restart at each startup boundary.
  • Before any authorized turn, a stall records a neutral startup deferral, leaves the source task retryable/Open, charges zero source attempt/retry/review/provider-health budget, and automatically starts exactly once after recovery.
  • Startup persistently creates coherent launch intent, attempt/fence, process epoch, capability, observer, and watchdog state; crash injection after each write/spawn boundary reconciles without orphan Pi processes or ambiguous attempts.
  • A trusted local worker with a valid bounded durable lease survives temporary coordinator IPC loss and continues; a stale fence, revoked lease, wrong task, wrong attempt, expired token, or process-epoch mismatch is refused.
  • Remote/untrusted and observation-only modes retain their configured fail-closed behavior.
  • If execution began before interruption, recovery preserves the worktree/session and correct attempt evidence; if it did not begin, status explicitly says so and never labels the source/scientific work failed.
  • Existing continuation authorization, stale capability, Pi watchdog, provider breaker, and attempt fencing tests remain green.
  • Add a credential-free terminal/daemon smoke scenario, run targeted tests, cargo fmt --check, cargo clippy, and git diff --check.

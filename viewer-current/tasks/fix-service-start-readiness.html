Description

Objective

Eliminate the daemon-less false-success/startup ambiguity in wg service start, especially immediately after wg service stop.

wg service start must return success only after a readiness handshake with the newly spawned daemon instance, not merely after process creation or socket appearance. Use an instance nonce/epoch or equivalent proof so a stale socket or delayed old-daemon response cannot satisfy readiness. Stop/start must safely handle PID/socket races.

On failure, exit nonzero and print an unmistakable stderr diagnostic containing the reason, relevant bounded daemon-log tail, and a concrete recovery command. Preserve machine-readable JSON behavior. Do not claim to make arbitrary shell pipelines safe; make direct command exit and stderr semantics correct and testable.

Validation

  • Add focused tests for fresh start, already-running behavior, immediate stop/start, stale socket, delayed old-instance response, child exit before readiness, and readiness timeout.
  • Add a PTY/terminal-level smoke scenario exercising the actual wg service stop → immediate wg service start human flow repeatedly and verifying each reported success has a responsive matching daemon.
  • Verify startup failure is nonzero and loud on stderr even when stdout is redirected; register the scenario in the grow-only smoke manifest with this task as owner.
  • Run the owned smoke scenario against the candidate binary plus focused Rust tests and cargo fmt --check.
  • Report exact changed files, validation output, and any remaining platform-specific risk.

Objective

Close the current Luna FLIP rejection against commit 4fee4439 and prove that genuine two-phase FLIP evidence—not self-asserted receipt fields—controls publication under the restarted authoritative binary.

Context: repair-landing-review-rejection implemented candidate-blind inference plus fresh comparison and semantic-rejection blocking, but its own completion was processed by the stale pre-fix daemon and was published despite current candidate-bound FlipRejected. Luna found that ReviewReceipt::has_genuine_flip_proof accepts a protocol string/nonempty routes and readable latent CID without independently binding the two executions, route snapshots, phase-I blindness, and hypothesis provenance. Its candidate also carried only git diff --check as authoritative deterministic-validation evidence.

Required behavior

  • Define immutable phase execution records for inference and comparison, each bound to task/generation/attempt/fence/candidate, exact route snapshot, prompt/input digest, output digest, start/finish chronology, executor, and usage/error outcome.
  • Bind the latent hypothesis CID to the successful phase-I execution output; bind phase II to that exact hypothesis CID and the revealed intent/evidence digest. A receipt cannot manufacture proof by filling protocol/routes/CID fields.
  • Prove phase-I blindness structurally: its canonical input schema/digest must exclude requirements/task description/conversation and reject forbidden fields. Phase II must be a fresh process/call and consume the immutable phase-I CID.
  • Make has_genuine_flip_proof validate the complete chain and reject missing, swapped, forged, stale, cross-candidate, reordered, same-call, or mutated evidence.
  • Preserve fail-closed authority: current FlipRejected/EvalRejected or invalid/inconclusive FLIP proof must not publish or mark Done; candidate/source attempt/session/worktree remain repairable. Eval runs only after genuine FLIP pass.
  • Capture every required validation as authoritative deterministic-validation envelopes, not worker-summary prose. Include focused Rust tests, changed-byte invalidation, three-agent FIFO/restart fencing smoke, plugin tests/embed sync, fmt/check, and clippy.
  • Do not run cargo install while the daemon is live. Use an explicit candidate binary for tests and leave final install/restart to the operator.

Validation

  • Negative tests reject forged protocol/routes/CID-only proof and every broken binding listed above.
  • Call-observation test proves exactly two isolated FLIP model calls, blind phase-I prompt reconstruction, fresh phase-II comparison, then Eval only after pass.
  • Real rejected candidate remains unlanded/Not Done under the authoritative candidate binary; repaired candidate with genuine FLIP+Eval passes and lands.
  • All requested command results are included as immutable deterministic-validation evidence in the completion manifest.
  • Owned FIFO/restart/plugin/embed/fmt/clippy/focused tests pass with exact command evidence.

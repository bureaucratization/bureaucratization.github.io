Description

Objective

Replace collision-prone post-hoc central conflict handling with a persistent FIFO landing-turn protocol. Concurrent agents may implement independently, but only one source agent at a time may integrate against the canonical target. The source agent that understands its change owns conflict resolution, renewed validation, and resubmission; WG owns the lease, queue, fencing, and final compare-and-fast-forward.

Required protocol

  1. Add a project/ref-scoped landing queue and short renewable lease, persisted under WG control state. A ticket is bound to task, generation, attempt, fence, candidate sequence, source agent/session, integration ref, and observed target OID. FIFO fairness must be deterministic.
  2. A worker requests its landing turn only when its candidate is ready. It does not hold the lease during ordinary implementation.
  3. If another landing owns the lease, atomically park through the existing AttemptParked/Waiting machinery with a typed landing-turn wait condition and checkpoint. Release worker/build capacity while retaining the exact worktree, candidate, Pi session continuation, and queue ticket.
  4. When the ticket reaches the head and the lease is available, the daemon automatically resumes that same task/session/worktree. The resumed source agent synchronizes with the current target, resolves conflicts in its own branch, reruns target-dependent validation, and submits a new candidate/receipt binding when bytes changed. It must never edit another worker's worktree.
  5. The finalizer may fast-path clean merges, but a content conflict returns ownership to the source agent instead of stranding a released worker or invoking an unrelated generic merger by default.
  6. Final publication is allowed only for the current lease owner and exact target/candidate/fence. Success releases the lease and wakes the next ticket. Death, timeout, cancellation, stale attempt, or failed renewal fences the old owner and advances safely; no lease can block forever.
  7. Bound lease duration and renewal to proven progress. Provide operator status/reclaim commands, but normal operation must be automatic.

CLI and Pi plugin

Expose the protocol in the wg binary with clear request/status/wait/release/reclaim verbs (choose one coherent command family). Extend wg wait with the typed landing-turn condition where appropriate.

Add Pi extension tools for at least:

  • wg_wait: park the current task on a validated condition with an optional checkpoint;
  • a landing-turn request/status operation needed by the source-agent flow.

Tools must shell through WgBackend, bind to the managed task/capability rather than trusting arbitrary task IDs, propagate nonzero errors, and be covered by plugin tests. Rebuild and commit worksgood-pi/embedded/ using make embed-worksgood-pi so hermetic workers receive the tools.

Safety and scope

Do not hold a filesystem lock across an unbounded model call. The persisted lease is the authority; an OS lock protects only short atomic queue/lease mutations. Do not weaken immutable completion receipts, target fencing, user-byte preservation, or post-integration validation. Existing clean, uncontended completion should remain fast.

Validation

  • Add state-machine tests for FIFO acquisition, parking, exact continuation resume, renew/release, stale fence, owner death, expiry, cancellation, restart recovery, and starvation freedom.
  • Add tests proving only the exact source agent/capability can resolve and land its candidate, and changed integration bytes invalidate old review/validation receipts.
  • Add Rust CLI and TypeScript plugin tests for wg_wait and landing-turn operations, including argument binding and error propagation.
  • Add a terminal-level smoke scenario with three concurrent source agents modifying the same grow-only manifest region. Each must park/resume/merge in turn; all three entries survive; no task remains in LandingPending; no manual git reset, rm-dep, or operator merge command is used. Register exactly this one task as the manifest writer/owner.
  • Add crash/restart smoke coverage showing an expired owner is fenced and the next ticket proceeds without losing the first candidate/worktree.
  • Run make embed-worksgood-pi, plugin tests, owned smoke scenarios against the candidate binary, focused Rust tests, cargo fmt, cargo fmt --check, and cargo clippy.
  • Run cargo install --path . --locked and verify the restarted daemon reports the candidate build identity.
  • Report changed files, exact validation evidence, lease invariants, and residual platform risks.

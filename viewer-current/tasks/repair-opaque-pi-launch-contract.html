Description

Objective

Fix the concrete NO-GO findings in docs/reports/pi-opaque-execution-boundary-verification.md. Preserve the approved architecture: WG authoring resolves once; runtime receives a complete immutable assignment; Pi interprets its opaque selection. Keep the experiment opt-in and preserve the working stable path. This task follows the active stable rehearsal to serialize shared config/runtime/smoke work; it is not a new scheduler or rewrite of the durable graph.

Required corrections

  1. Accept a genuinely Pi-native opaque selection at the authoring boundary. Validate the outer pi: envelope and nonempty safe data, NOT a provider/model colon grammar. For the tested Pi CLI, pi:openai-codex/gpt-5.6-sol must reach Pi as openai-codex/gpt-5.6-sol unchanged. That is an example, not a naming rule: colons/slashes/aliases understood by Pi must not be reinterpreted by WG. Never fix the dialect mismatch by splitting/normalizing after assignment. Provide an explicit, loss-aware migration for DECLARED legacy WG provider/model syntax; never heuristically rewrite arbitrary opaque strings or mutate current operator selections. Preserve historical attempts and stable-path compatibility.
  2. Bind the effective launch plan once: exact executable, relevant fixed argv, configuration root and nonsecret config identity, explicit tool/extension policy, cwd, reasoning, session/prompt policy and applicable timeout/network policy. Preflight and execution consume that same plan; phase-specific differences must be explicit (capability query versus execution), not hidden second resolution. Worker and hermetic review may have different declared policies, but each must preflight against its OWN actual execution context. Persist enough identity for review/one-shot attribution, not only a route label. Do not serialize credentials/tokens or freeze Pi token refresh; use safe references/digests and document the supported mutable authentication boundary. Unexpected configured invocation changes after pinning must be detected, not silently alter the attempt.
  3. Connect the accepted managed-process/RPC adapter to this assignment without provider/model re-inference. Preserve subscribe-before-yield, same-session wake, cancellation, restart ownership and bounded deadlines. Fix the prior real cancellation finding: adapter termination must use correctly established owned process/session groups and clean/reap descendants through the PRODUCTION path, not only an external negative-PGID test wrapper. Preserve unrelated processes and fail closed on ambiguous ownership.
  4. Preserve typed admission/review blockers through worker wrappers. Strict unavailable review or a pending explicit decision must not become generic worker failure or consume retry budgets. Unsupported/invalid selection must not consume attempts or cycle restarts. Coalesce repeated unchanged admission notifications; do not emit the same backoff warning on every tick.

Validation

  • Real current Pi accepts a Pi-native opaque selection through actual WG worker AND reviewer launch, performs one useful neutral non-Rust task, and records exact unchanged selection, pinned invocation, result and one publication. Existing Pi-owned auth only; no alternate model to disguise a failed test.
  • Preflight and launch use the same bound provider-registration/configuration/extension context. Tests cover changed config, conflicting argv, unusual opaque values and explicit legacy migration with no post-boundary re-resolution.
  • Real managed command starts once, yields, wakes the same authorized session, and returns usable result evidence. Exercise the ACTUAL adapter timeout/cancellation path; all owned descendants exit/reap, unrelated process survives, and completion-before-yield/duplicate events cannot rerun work.
  • Restart preserves the assignment and actual blocker; strict unavailable review remains strict without false source-quality failure. Invalid configuration does not spend retries; unchanged admission warning is deduplicated.
  • Preserve graph/history/read compatibility, explicit current role/tier overrides and stable behavior. Both review modes remain honest; advisory findings are not labeled passes. No automatic experimental rollout.
  • Use the existing worker-selected candidate evidence mechanism for focused checks and real human-flow proof. Run applicable repository CI checks and owned entry-point smoke; do not invent additional hard gates or acceptance requirements about progress messages/historical chronology/future own receipts.

Use existing modules and primitives, not another model registry or process manager. Managed worktree and canonical project scratch only. No global install, live daemon restart, origin/main push, credentials copy or live route changes. The operator separately deploys after verification. Record tested supported runtime boundary and any unresolved limitation; do not call a fake-Pi fixture a real-provider success.

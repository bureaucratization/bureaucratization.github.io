Broker scoped quality-pass edits without blocking the batch

Description

Fix the quality-pass authority/lifecycle contradiction exposed by worker_control.cross_task_refused: a quality-pass worker can successfully inspect its declared batch but is currently instructed to edit/assign/release downstream tasks while worker control authorizes only its own source task. This makes the generated task impossible and can block an entire batch behind a failed optional optimization pass.

Do not remove cross-task isolation globally. Replace direct arbitrary sibling mutation with a bounded brokered protocol. Preferred shape: the quality-pass worker emits a structured TaskPatchPlan covering an immutable allowlist of batch task IDs and allowed metadata operations; a trusted coordinator validates and atomically applies the plan. Bind authority to quality-pass task generation/attempt/fence and batch digest, expire it after one consumption, reject additions or unrelated targets, and preserve provenance of proposed/applied changes. Allowed fields should be explicit (for example classification, description/validation clarification, tags, priority, route/reasoning, assignment recommendation); dependency/lifecycle operations require separate typed rules. Never permit delete, done/fail, validation weakening, arbitrary dependency removal, or mutation outside the declared batch.

Fix batch release semantics so an optional quality pass cannot gum up the graph. The coordinator, not the LLM worker, owns staging/release. On valid plan, apply atomically then release the batch. On model/provider/infrastructure failure or invalid plan, record a loud advisory failure and release original tasks unchanged unless the user explicitly selected a required quality gate. Do not wire ordinary hard dependency edges whose failure permanently blocks the batch. Partial mutation followed by failure must be impossible or transactionally recoverable.

Add admission/preflight validation: a task whose declared operations exceed its granted control scope must be rejected before spending an LLM call, with an actionable diagnostic identifying the missing capability/protocol. Update the universal agent guide/quality-pass templates so they no longer instruct workers to run impossible direct wg edit/wg assign/wg resume sequences.

Expose the quality-pass activity in the parent batch/task UX as non-authoritative internal activity, consistent with the evaluation-cutover activity model. This task must not weaken the existing refusal for ordinary workers.

Validation

  • Reproduce the current failure with a staged two-task batch: the old direct downstream edit receives worker_control.cross_task_refused and no target is mutated.
  • In the new path, a quality-pass worker can submit one structured plan for exactly its declared batch; the coordinator validates, applies all allowed changes atomically, records provenance, and releases both tasks.
  • Attempts to target an unrelated task, alter forbidden fields, weaken/remove validation, delete/complete/fail a task, reuse the plan, or submit from a stale attempt/fence are refused with zero mutation.
  • Provider failure, malformed output, timeout, and quality-pass task failure release the original batch unchanged with a visible advisory warning by default; an explicitly required gate remains fail-closed.
  • Crash tests around plan persistence/application/release prove exactly-once recovery and no half-applied batch.
  • Ordinary workers remain own-task scoped and all existing worker_control.cross_task_refused security tests continue passing.
  • Agent guide/templates, CLI/JSON status, and TUI explain proposed/applied/skipped/failed quality-pass activity and whether the batch was released unchanged.
  • Targeted tests, new isolated fake-provider smoke scenario, cargo fmt --check, cargo clippy, and git diff --check pass.

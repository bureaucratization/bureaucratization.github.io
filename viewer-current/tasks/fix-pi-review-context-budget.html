Description

Objective

Make candidate-bound Pi FLIP/Eval reviews actually execute on the configured weak route instead of silently producing ReviewUnavailable because ambient repository context exceeds the model window.

Confirmed live failure: pi:openrouter:deepseek/deepseek-chat receives about 37.8k input tokens even for a two-word probe and DeepInfra rejects it because max_num_tokens is 32768. WG's one-shot args already disable extensions, tools, and sessions, but do not pass Pi's --no-context-files; Pi therefore loads the repository's large AGENTS.md/CLAUDE.md into a hermetic reviewer that already receives an explicit review bundle. The Pi NDJSON contains the precise upstream stopReason=error / errorMessage, but WG collapses this to Empty response from pi CLI.

Required behavior

  • Add --no-context-files (-nc) to all WG Pi lightweight/agency/FLIP/Eval one-shot invocations where WG supplies the complete prompt. Do not affect full worker/chat sessions.
  • Keep --no-tools, extension discovery disabled, and --no-session; do not add provider fallbacks or consult WG secrets.
  • Parse Pi terminal error events and surface the exact bounded upstream error category/message rather than reporting an empty response.
  • Preserve candidate/task/generation/fence binding and the rule that Eval runs only after an exact FLIP pass.
  • Make wg show/activity clearly distinguish attempted+failed, FLIP pass, and Eval pass.

Validation

  • Argument tests prove the one-shot Pi command includes no-context-files/no-tools/no-extensions/no-session while full Pi workers do not inherit this restriction.
  • A fake-Pi integration test with a huge repository AGENTS.md proves ambient context is excluded and the explicit reviewer prompt is still delivered.
  • NDJSON parser tests prove an upstream context-window error is reported specifically, never as empty response.
  • End-to-end completion-review test proves a FLIP pass is followed by Eval and both exact candidate-bound receipts/activity records are persisted; rejection/unavailable paths remain correctly distinguished.
  • Run focused Rust tests, cargo fmt, cargo fmt --check, and cargo clippy. Add smoke coverage only if it can exercise a real route under the repository smoke contract; do not add a fake-provider smoke.
  • Report exact commands, changed files, and residual provider-specific context risks.

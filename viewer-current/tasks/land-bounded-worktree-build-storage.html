Description

The previously implemented build-storage fix never landed. Recover and port the bounded copy-on-write Cargo target design from commit 07abed93 / origin/wg/agent-17/fix-worktree-cow-build-storage onto current main, without blindly merging its unrelated old-base harness reshuffle.

Incident evidence: three completed worktrees each grew to 69-70 GiB and filled the 437 GiB filesystem; the current completion-resilience worker grew from 4.8 GiB to 20 GiB within minutes. Current main still assigns each worktree a complete private target directory, records a legacy heavy-build high-water near 95 GiB, defaults predictive admission off, and retains stale cache ownership entries after worktree deletion. Manual removal is not an acceptable lifecycle.

Implement the current-architecture storage contract:

  • One immutable, content-keyed Cargo baseline per exact build key (toolchain, lockfile/features/profile/config inputs), plus a per-attempt writable layer seeded using safe physical sharing/reflinks/hardlinks only where mutation cannot corrupt the baseline.
  • Count and reserve physical private delta, not repeated logical baseline bytes. Migrate legacy full-tree high-water safely.
  • Give workers the owned layer via CARGO_TARGET_DIR; use bounded debug/incremental settings where compatible.
  • On done/fail/wait/owner loss, release exact leases and reap terminal private layers once source/artifact/live-process guards pass. Missing worktree paths and expired owners must not remain permanently active/inconclusive.
  • Predictive admission should be safe-by-default for new configs, while explicit emergency overrides remain visible. Do not permit N full 70-95 GiB targets to start concurrently.
  • Preserve dirty/unmerged source and registered artifacts. Cleanup may delete only exact owned build caches, never source.
  • Repair ownership registry compaction for deleted paths and dead/purged agents.
  • Keep the port narrowly scoped; current main already contains later completion/lifecycle changes.

Validation

  • Candidate-binary smoke launches at least three isolated build workers and proves physical usage is one baseline plus bounded private deltas, not N complete target trees.
  • Repeated no-change builds reuse the immutable baseline and do not grow storage linearly.
  • Concurrent divergent builds cannot mutate/corrupt each other's outputs or the baseline.
  • Terminal work removes private layers automatically; restart between exit and cleanup converges idempotently.
  • Deleted worktrees/dead registry owners are compacted from owned-caches and do not remain active/inconclusive.
  • Dirty source and registered artifacts remain byte-identical through cleanup.
  • ENOSPC/headroom simulation defers before spawn without creating an attempt; recovery dispatches exactly once.
  • Migration ignores the legacy ~95 GiB full-tree high-water and records private-delta schema.
  • Measure logical and physical bytes in tests and report both.
  • cargo fmt --check
  • focused target-cache/disk-sentinel tests
  • credential-free smoke scenario
  • git diff --check

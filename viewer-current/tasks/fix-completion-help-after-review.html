Description

Objective

Close the specific rehearsal-proven hole in the landed completion repair loop, without another framework. src/commands/fail.rs::preserve_completion_repair rejects every explicit help/correction intent when task.completion_repair is absent, with requires an evidence-backed deterministic completion failure. first-user-release-rehearsal had genuine exact FLIP rejection and needed an operator-approved evidence/validation correction, but both --intent request-help and --intent request-contract-correction refused. Current retained rehearsal candidate is 64a08810; inspect its task message and current immutable review findings. This is not authority to accept its work or call its logs authoritative.

Required behavior

An authorized current worker must be able to explicitly request help or propose a contract correction after a current semantic completion rejection as well as a deterministic validation failure. Bind to verified current source attempt/candidate/review receipt and preserve the strict rejection and all evidence. Asking for help is NOT acceptance, not permission to lower gates, not a provider retry and not an automatic source/reviewer rerun. Use existing attention representation and terminal/continuation authority where possible; do not manufacture a deterministic-failure receipt to fit an API or create parallel scheduler/task hierarchy.

Keep requests idempotent, bounded and redacted, with the current actual blocker, saved work and one actionable operator decision visible through existing status/show/notification surfaces. Preserve candidate and worktree even if worker exits. Treat explicit deliberate-stop distinctly: never require a test failure merely for an authorized worker to state inability to proceed, and do not silently reactivate a deliberate stop. Wrong-task/wrong-attempt/stale-candidate requests are rejected. Existing semantic evidence remains unaccepted until ordinary approved contract revision, new validation and review succeed. A later timeout must not erase the pending explicit operator decision from primary status.

Generic core behavior only: no Cargo-specific classification, command inference, provider fallback, test exclusions, review bypass or relaxed capability boundaries. Do not extend into broad preflight/UX redesign; reuse landed mechanisms. Review/authority validators must still reject forged or superseded receipts.

Validation

  • Extend existing commands::fail and completion canary tests to exercise current deterministic failure, current FLIP rejection, current Eval rejection, deliberate stop and both help intents with exact identity checks.
  • Real candidate CLI fixture in integration_smoke_gate demonstrates semantic rejection -> request-contract-correction -> persistent visible attention -> explicit approved contract update -> invalidation of stale binding -> ordinary revalidation/review, never acceptance at request time. Distinguish deterministic controlled review fixtures from live semantic proof.
  • Same request replay/daemon restart/worker exit keeps one attention item and the semantic blocker; timeout classification cannot conceal it. No unchanged reviewer call is scheduled by a help request.
  • No fabricated deterministic receipt, altered old rejection, scope widening, wrong-task write, stale attempt, or unapproved gate modification. Deliberate stop stays stopped.
  • Actual status/CLI flow gives one precise next action and preserved-work location; use integration fixtures covered by the configured gate for host-captured evidence, and register applicable owned smoke.
  • Full assigned fmt/clippy/fail/canary/library/integration gate passes with exact candidate immutable evidence. Request any missing authoritative command BEFORE review rather than resubmitting logs-only evidence.

Execution discipline

Managed worktree, canonical project scratch outside source .wg, explicit candidate binaries, isolated test HOME/config/child environment. No global install, live daemon restart, origin/main push or root checkout merge. Keep repair small; preserve all prior source/review history. Host-bound evidence identifies the candidate; reports never claim an earlier implementation hash is their own future commit. Operator separately deploys the landed binary and recovers the retained rehearsal with an approved evidence contract.

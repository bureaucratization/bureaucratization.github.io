Objective

Design how to restore the useful assign → execute → FLIP/evaluate → learn → improve cycle without restoring schedulable synthetic graph satellites or lifecycle deadlocks.

Start from the current completion-review receipts, receipt-backed scored evaluation, agency performance/evolver stores, and the recommendations in docs/audit/2026-08-08-worksgood-system/23-evaluation-evolvability-cutover.md. Define one coherent authority map and data flow:

  • attempt-bound assignment receipt (or explicit uncomposed dispatch);
  • append-only candidate FLIP/Eval attempt ledger with route, timing, findings, usage/cost, supersession, and exact manifest/source binding;
  • virtual non-schedulable .flip/.evaluate projections for familiar visibility;
  • one terminal generation learning episode, exactly once, so repeated rejected candidates do not multiply task count;
  • separate reviewer calibration and infrastructure reliability from source quality;
  • delayed assignment reward and evolver input;
  • optional automatic assignment that never blocks the source on an ordinary graph edge.

Produce docs/design-adaptive-agency-loop.md with schemas, capability boundaries, migration relationship, rollout phases, and an executable acceptance matrix. Explicitly distinguish completion review, candidate evaluation, scored outcome evaluation, and external adjudication.

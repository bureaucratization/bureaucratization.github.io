Description

Repair completed-task Pi accounting and completion-review observability. Live evidence in this repository shows 11 of 12 done audit tasks have many turn_end.message.usage records in .wg/agents/<agent>/raw_stream.jsonl, but their graph tasks have token_usage = null, actual_executor = null, and actual_model = null; consequently wg spend reports only one task. Example: audit-documentation has 82 raw turn_end records and provider-reported cost, yet wg show --json has no usage/model/executor. Also, exact FLIP and eval reviews are enforced and leave immutable receipts, but wg list --all shows no review nodes and users cannot readily see or attribute their model calls/costs; only .chat-0 is visible.

Reproduce this with bounded fake-Pi fixtures and trace worker spawn, raw capture, pi-stream bridge/finalization, graph usage persistence, agent archival, completion review, and show/spend/trace rendering. Fix the authoritative path rather than scraping current live files. Preserve once-per-turn deduplication and distinguish source-worker usage from FLIP/eval reviewer usage so totals are not double-counted. Retain actual executor/model after completion. Provide an explicit, understandable surface for completion-review activity (whether internal lane records rather than graph tasks), and make wg list --all/help semantics clear so users do not infer that reviews did not run. Consider a safe repair/backfill path for existing raw streams only if it can be content-bound and idempotent; do not silently estimate missing usage.

Validation

  • A deterministic Pi worker fixture that reaches Done persists nonzero, correctly deduplicated task token usage and provider-reported cost, plus actual executor/model.
  • The same accounting survives completion review, landing, agent archival/cleanup, and service restart.
  • wg show and wg spend display the completed task; totals do not double-count repeated Pi usage snapshots.
  • Exact FLIP/eval reviewer executions and receipts are visibly attributable as internal review-lane activity, with their usage/cost labeled separately when available; help explains why they are or are not task nodes.
  • Regression coverage includes the currently observed raw-stream-present/graph-usage-missing failure path and a failure/timeout path.
  • cargo fmt --check, targeted tests, cargo clippy, and git diff --check pass; run owned smoke scenarios if the manifest assigns any.

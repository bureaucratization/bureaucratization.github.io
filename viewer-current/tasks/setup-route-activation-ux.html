Description

Investigate and improve the wg setup first-run route/profile/authentication experience as an independent product task. The reported symptom is that a user can complete wg setup with their intended options but still appears to need a separate wg profile use <profile> step, while model/login availability is not checked or explained clearly enough.

Start from clean, isolated HOME and project fixtures. Trace setup, route selection, profile activation, active-profile persistence, config generation/reload, model discovery/validation, handler authentication ownership, and the first LLM-backed command. Determine the exact current behavior before changing it. Then implement the smallest coherent UX so a successful setup leaves the selected route/profile actually active and ready without an undocumented follow-up command. Where live credential verification is provider/CLI-owned or cannot be safely automated, provide an explicit bounded preflight/status result and actionable next command rather than claiming readiness. Preserve handler-first model semantics and do not introduce cross-provider fallback.

Add deterministic tests using isolated homes and fake handlers/providers; do not require or alter real credentials. Update CLI help or canonical setup documentation when behavior changes. Record any design ambiguity that needs human adjudication rather than guessing.

Description

Fix the process-lifecycle leak discovered on 2026-08-17: sixteen pi Node processes from pi_threshold_compaction_same_process_kick survived for ~10.5 days with PPID 1 and deleted working directories/log files. Their environment identified WG_TASK_ID=pi-kick-smoke, WG_SMOKE_SCENARIO=pi_threshold_compaction_same_process_kick, and fake model fake-pi-compaction-stall:fake-long-agentic-turn. Each retained roughly 2.9-3.8 GiB RSS, together consuming about 50 GiB, and each held a defunct wg child. Additional smoke wrappers/observers and service daemons also escaped teardown.

Implement robust smoke-process ownership and cleanup without matching/killing unrelated user Pi sessions:

  • Every scenario-launched daemon, wrapper, observer, fake provider, and real Pi subprocess must belong to an explicitly recorded process group/session or equivalent ownership set.
  • EXIT/ERR/INT/TERM cleanup must terminate the whole owned tree, wait/reap it, and only then delete temp directories.
  • Cleanup must handle double-fork/orphan behavior, TERM-ignoring fixtures, daemon supervisors, failed assertions, shell interruption, and already-exited parents.
  • The global smoke harness must provide a final backstop keyed by scenario-owned process identity, never command-name-only matching.
  • Persist enough bounded diagnostics on cleanup failure to identify PID, start identity, process group, and scenario.
  • Audit similar smoke scenarios for the same leak pattern.

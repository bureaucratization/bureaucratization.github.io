Description

Objective

Implement the user-approved lighter completion experience in the CURRENT WG completion/worker path: accepted, concrete repair feedback to the SAME worker, or one explicit request for human help. Preserve the current receipts, candidate binding, lease/fence authority and fail-closed publication underneath. Do not add a scheduler, synthetic repair tasks, diagnosis-agent fleet, or parallel lifecycle authority. Reuse existing outcomes, continuation, budgets, blockers and notification mechanisms wherever possible; new lifecycle states require demonstrated necessity, not convenience.

Incident and boundary

fix-smoke-pi-process-leaks had green focused tests but the existing required broad cargo test --locked smoke --no-fail-fast failed. The worker classified those failures as pre-existing/out-of-scope and called wg fail, leaving first-user-release-rehearsal indefinitely blocked until the operator expanded repair scope. The gate was right to reject; the repair handoff and visibility were inadequate. The worker is now repairing that incident independently; depend on its successful completion and reuse its concrete regression lessons. This task changes normal completion behavior, not historical receipts or the prior task acceptance criteria.

Required small implementation

  1. Pre-dispatch validation clarity. Resolve and present the actual required deterministic checks, their provenance, and the worker permitted repair boundary before it starts. A broad gate plus narrow feature scope must explicitly distinguish permitted test/fixture repairs from changes requiring approval. Do not infer blanket permission to change arbitrary production code or reduce gates. Use a small documented policy/default/override in existing task or contract mechanisms rather than another workflow language. Scope/contract changes after dispatch must become explicit feedback and invalidate stale binding through supported rules, not silently change acceptance.
  2. Same-worker repair. A failed deterministic completion check normally returns structured, bounded repair feedback to the current source worker, with command/exit category, concise redacted diagnostic excerpt, immutable evidence reference, candidate identity and one next action. Preserve session/worktree/attempt authority through existing continuation machinery; do not terminally fail an in-scope repairable task merely because the check failed. Do not invoke a semantic model to classify a known command failure. Existing semantic rejection also stays fail-closed and uses its authorized repair path; do not retry a reviewer until it agrees.
  3. Bounded repair and escalation. Reuse the existing repair/rejection budget where applicable, with a small explicit deterministic-repair budget (default two repair opportunities unless existing validated semantics justify another documented bound). Bind the failure/progress accounting to the proper source attempt, candidate and validation identity. Restart, duplicate feedback and cosmetic output must not replenish the budget; meaningful changed work may advance an attempt but cannot extend the total episode indefinitely. Detect unchanged repeated submissions deterministically. On exhausted budget, unknown classification, scope ambiguity, or missing authority, retain saved work and expose NeedsAttention through existing representations with one specific decision/request. Transport failures use existing bounded infrastructure policy only when safely classified; never route validation/authority failure through provider backoff. User pause/cancel, explicit intentional abandonment, security/integrity rejection and unsafe session recovery remain authoritative. Do not simply forbid every wg fail; distinguish deliberate stop from a repairable completion failure using existing structured evidence.
  4. Visible stalled-chain reporting. Status/show JSON and human output, plus the existing TUI blocker surface, must prominently explain the ROOT blocker, whether anyone is actively repairing it, affected downstream work, and the one safe operator action. Use deterministic read-only graph/evidence projection, not a mutable second scheduler. Traverse cycle-safe with deduplication; cycles are supported and not themselves proof of a stall. Active work or a valid bounded wait is not stalled. Publish a deduplicated attention event through the EXISTING originating-chat/notification bridge if available; document unsupported delivery surfaces instead of inventing a new notification backend. Repeated daemon ticks/restarts must not spam or invoke models.

Validation

  • Real worker/CLI completion fixture: initial required check fails, SAME authorized session/worktree receives concrete evidence-backed feedback, repairs, reruns the unchanged required gate, and publishes exactly once. No manual retry, dependency deletion, fabricated evidence or helper task is used.
  • Out-of-scope failure requests one explicit approval and preserves work; operator-approved scope update is recorded and invalidates stale acceptance binding. No silent gate relaxation or blanket authority escalation.
  • Repeated unchanged failure and total repair-budget exhaustion produce visible NeedsAttention without looping, duplicate publication or model-only diagnostic calls. Restart/replay preserve budget and deduplicate feedback/events.
  • Contract checks exposed before execution match the checks actually enforced. Validation output excerpts are bounded/redacted and untrusted text cannot authorize execution or expand scope.
  • Negative cases preserve explicit pause/cancel/abandonment, security fences, semantic rejection, invalid credentials, ambiguous interrupted execution, missing session proof and out-of-scope repair boundaries.
  • Actual CLI/PTY and TUI flow shows one root blocker and next action for a stalled dependency chain, no false stall for an active repair or valid timed wait, and terminates/deduplicates on cyclic graphs.
  • Register owned real-entry-point smoke coverage with this task as owner and test explicit candidate binaries; use integration fixtures for fake sessions/clocks where required by smoke policy. Preserve existing completion-canary, semantic-rejection and continuation/session-fence tests.
  • cargo test --locked --bin wg commands::completion_canary_tests; targeted new completion/continuation/blocker tests; cargo fmt, cargo fmt --check, cargo clippy, and git diff --check pass. Run applicable existing required gate suite and fix failures without narrowing it.
  • Briefly document the user-facing completion/repair/help contract and exact permitted repair boundary. Record executed immutable evidence available BEFORE review; future own review/publication/reload receipts are operator postconditions, not candidate inputs.

Distinguish repair, intentional cannot-complete stop, and request-contract-correction using existing authority. Reports may cite prior implementation revisions but must not need their own future hash; exact-candidate validation comes from host-bound evidence. Preserve semantic blockers even when a later provider error is also recorded so status does not misleadingly present every stop as a transient provider outage.

Description

Objective

Stop placing new WG build/install scratch under the daemon process's OS temp directory by default. The default scratch root must live on the current WG project's filesystem so admission and displayed headroom reflect where the project is actually building, not /tmp/the root filesystem.

Use the resolved WG project root—not the daemon's incidental process launch directory—as the authority. A suitable managed default is under .wg/ (for example .wg/build-tmp/<agent>), so it remains control-plane/runtime data and cannot dirty Git. Preserve explicit dispatcher.resource_management.build_tmp_root overrides: absolute paths remain absolute and relative paths remain project-relative.

Update all related behavior coherently:

  • build_tmp_path_for_agent and spawned TMPDIR use the project-local default;
  • disk-sentinel configured mounts represent paths WG actually writes to and do not unconditionally admit/refuse based on unused OS /tmp;
  • explicit Cargo target/cache roots on other mounts are still measured;
  • active legacy owned scratch already under /tmp remains visible/protected until safely released or cleaned, but no new default allocation goes there;
  • human and JSON disk output identify the probed path/source clearly enough to distinguish project scratch, target cache, and configured overrides.

Do not confuse process CWD with project identity: wg --dir ... and a daemon launched from another directory must still resolve scratch beside that selected project's .wg state.

Validation

  • Add focused path-resolution tests proving the default is inside the selected project, never std::env::temp_dir(), across ordinary cwd, --dir, and daemon-style invocation from another cwd.
  • Add tests proving explicit relative and absolute build_tmp_root overrides retain their documented semantics.
  • Add mount-selection tests where project and /tmp are modeled as different filesystems: unused low-space /tmp must not block a project-local build, while low space on the actual project scratch or configured target-cache mount must block.
  • Add compatibility tests showing active legacy owned /tmp scratch remains accounted/preserved until stale cleanup is safe.
  • Add a terminal-level smoke scenario that launches the real daemon, dispatches a build-capable task, inspects its TMPDIR and wg disk doctor --json, and proves the default scratch and admission mount belong to the selected project rather than /tmp. Register it in the grow-only smoke manifest with this task as owner.
  • Run the owned smoke scenario against the candidate binary, focused Rust tests, and cargo fmt --check.
  • Report changed files, exact validation output, migration/cleanup behavior for old scratch, and residual risks.

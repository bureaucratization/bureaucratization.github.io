Description

Objective

Implement ONLY the accepted narrowed provider-backoff-contract against the CURRENT production dispatcher, not retired PlannerStore or ConvergenceState. The historical task ID is retained for continuity, not an architectural instruction.

Provide explicit opt-in bounded automatic retries for clearly evidenced transient SOURCE-provider failures. Disabled retains fail-stop behavior. Use a small attempt budget plus elapsed-time budget; baseline contract proposal is three automatic retries within fifteen minutes. Honor Retry-After without retrying earlier than the provider allows; if no retry fits the remaining budget, preserve work and request attention. Exact handler/model/route remains unchanged.

Persist failure episode identity, attempts used, first failure/window expiry, next retry, exact route and relevant evidence/fence identity through the existing authority. Duplicate evidence and restart must not increment twice, reset budgets, duplicate due attempts, or duplicate publication. Reconcile ambiguous interrupted execution before retry; refuse automation if safety cannot be established. Respect existing dispatch admission and route protections, user pause/cancel, and explicit manual retry semantics.

No automatic retry for semantic/review rejection, bad credentials/config/credit, completion-authority/integrity failures, or ambiguous unreconciled execution. Direct provider evidence must not trigger semantic model calls or synthetic quality scores. Do not add evaluator-only recovery, Agency projection/learning, rich TUI controls, hour/day backoff or a new scheduler/probe subsystem.

Include MINIMAL status/show and documentation: retrying/waiting/needs-attention, attempts and window remaining, next retry time, concise redacted reason and one safe operator action. Keep this with implementation; the separate rich UX task is deferred. Exhaustion is infrastructure NeedsAttention, not a quality verdict. Use existing representations where possible, documenting any necessary compatibility change.

Validation

  • Focused tests prove exact budget/window boundaries, Retry-After within and beyond budget, stable restart, duplicate evidence handling, and explicit reset rules.
  • Due retry creates one fenced source attempt; early/stale/replayed wake does nothing; ambiguous execution is not blindly rerun.
  • Pause/cancel, semantic rejection, auth/config/credit and authority failures never enter transient automation.
  • Existing completion-review policy and candidate receipts are preserved; no source rerun for reviewer-only failure.
  • Minimal CLI status/show presents truthful retry/attention and next-action information with secrets redacted; actual CLI/PTY flow is exercised.
  • Targeted current-dispatcher/integration tests and applicable owned real-entry-point smoke pass with the explicit candidate binary.
  • cargo fmt, cargo fmt --check, cargo clippy, and git diff --check pass; attach actual evidence.

Execution constraints

Use the current managed worktree and current main; preserve retained work and immutable evidence. Use Pi on the exact project Codex route with no fallback or WG secrets. No global install, daemon restart, root-checkout merge, or origin/main push by workers. Test explicit candidate binaries with project-local scratch. Capture actual validation through supported immutable evidence APIs; do not invent hard gates or require the candidate own future review/publication receipts as input. Never weaken lifecycle, review, or publication fences.

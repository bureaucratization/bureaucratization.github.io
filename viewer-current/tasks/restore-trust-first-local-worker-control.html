Description

Restore WG's trust-first local worker model. Recent worker-control policy defaults trusted local task agents to own-task-only graph authority, producing repeated worker_control.cross_task_refused failures for legitimate coordination such as quality passes editing downstream task metadata. Reconstruct the prior flexible behavior from Git history and current invariants, then implement the smallest coherent rollback/redesign: trusted local workers should be able to coordinate and mutate the project graph through the normal WG CLI by default. Narrow graph scopes remain available only when explicitly selected or when the actor is structurally untrusted (review/evaluator observation lanes, remote/federated providers, sandboxed inbound content).

Do not replace agency with a new broker/allowlist ceremony. A local worker spawned by this graph in the normal trusted mode should be able to inspect and edit sibling/downstream task metadata, create/link tasks, assign/reprioritize, message, and perform normal coordination operations subject to the same lifecycle/integrity checks as an operator. Target inequality (target_task != source_task) must not itself be a refusal reason for a trusted local worker.

Preserve integrity, not paternalistic permission boundaries:

  • every mutation remains actor/attempt attributed in the append-only lifecycle/event history;
  • stale/lost attempt fencing and compare-and-swap invariants remain enforced;
  • immutable candidate manifests, review receipts, and ledger evidence cannot be forged or rewritten;
  • completion still follows the canonical receipt-backed lifecycle rather than direct state corruption;
  • graph writes remain transactional/recoverable where the existing command provides that guarantee. These invariants protect consistency and auditability without assuming the worker is hostile.

Introduce or clarify an explicit, visible control policy such as trusted/scoped/read-only. Trusted must be the default for ordinary local workers and existing projects that did not explicitly opt into strict scoping. Scoped/read-only remain opt-in project/task policies and the automatic mode for genuinely observation-only or remote/untrusted actors. Preserve explicit strict configurations. At spawn and in wg show/status/TUI, state the effective control mode and important restrictions; provide a worker-readable capability command so impossible instructions are visible before work begins.

Repair the quality-pass path as the motivating end-to-end proof. Its local worker must be able to apply intended downstream edits directly through normal WG commands, with ordinary audit history. Optional quality-pass provider/infrastructure failure must not permanently strand the batch: release unchanged tasks with a loud warning unless the user explicitly configured the pass as required. Do not make normal downstream tasks depend forever on a failed advisory optimization.

Audit other built-in prompts/system tasks for the same impossible pattern: instructions to coordinate siblings paired with own-task-only authority. Correct the general policy rather than adding one-off exceptions. Update universal agent guide, worker prompt, Pi extension handshake/docs, and configuration migration/help as needed.

Validation

  • Historical regression fixture demonstrates the former trust-first local worker can perform legitimate cross-task coordination; current pre-fix fixture reproduces worker_control.cross_task_refused.
  • Under default configuration, a normal isolated local worker successfully edits declared downstream descriptions/validation, creates and links a subtask, assigns/reprioritizes, and records messages through public WG commands; all mutations are attributed to its exact actor/attempt.
  • The quality-pass end-to-end fixture audits a batch, edits downstream task metadata, and releases it without scope refusal. Provider failure releases the unmodified batch with a visible advisory warning; explicit required mode remains fail-closed.
  • A stale/reaped worker still cannot write after losing its fence; immutable manifests/receipts remain immutable; canonical completion cannot be bypassed.
  • Explicit scoped mode still refuses unrelated cross-task writes, and observation-only evaluator/reviewer plus remote/untrusted fixtures remain scoped regardless of the local default.
  • Effective trusted/scoped/read-only mode and restrictions are visible in CLI/JSON/TUI and in the worker's startup context before an LLM call attempts an impossible operation.
  • Search all shipped worker/system prompts for cross-task instructions and prove each runs under compatible authority.
  • Targeted unit/integration tests, an isolated fake-provider smoke scenario, cargo fmt --check, cargo clippy, and git diff --check pass.

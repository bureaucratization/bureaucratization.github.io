Objective

Audit and finish the Pi-only, project-local-by-default configuration contract described by the user. Prior tasks (project-local-pi-design, project-local-pi-core, project-local-pi-cli, project-local-pi-migrate, project-local-pi-e2e) implemented much of this surface; verify every requirement against current code and close remaining gaps rather than duplicating or weakening it.

Required behavior

  • Pi authentication and provider credentials remain entirely Pi-owned; Pi-only WG operation must not require WG secrets, ~/.wg/config.toml, or ~/.wg/active-profile.
  • Model routes, reasoning, resource limits, archival policy, and other project behavior resolve from a checked-in project configuration by default.
  • wg setup, ordinary wg config writes, and profile association are project-local by default. Global writes require explicit --global and an advance warning naming the affected path/scope.
  • Provide/confirm wg profile select as the project-local association command. Deprecate or clearly warn on globally mutating wg profile use; it must not silently change unrelated repositories.
  • Reusable definitions may remain under ~/.wg/profiles/, but selecting one applies a local association/overlay without copying unrelated values or clearing project guardrails.
  • Every effective-setting inspection surface reports the winning value and source layer. Ambiguous or missing local Pi route fails loudly instead of inheriting stale global routing.
  • Preserve identity, federation, secrets, and reusable profiles when migrating. wg migrate project-local-pi --cleanup-global-routing (or the canonical equivalent) must be dry-runnable, idempotent, narrowly remove stale global routing/active-profile state, and clearly report retained data.
  • Resolve the canonical checked-in filename deliberately. Current WG work may use root worksgood.toml while this proposal names .wg/config.toml; do not create two silently competing authorities. Implement a documented compatibility/migration rule and one deterministic precedence model.
  • Ensure one repository's setup/profile/config operation cannot alter another repository's effective route.

Validation

  • Fresh HOME with only Pi authentication and a cloned project works without WG global config/secrets.
  • Two-project isolation test proves setup/profile/config changes in A do not change B.
  • Missing local route fails loudly even when stale global routing exists.
  • Explicit --global warns and changes only the named global layer.
  • Profile selection preserves local guardrails and shows winning sources.
  • Migration dry-run/apply/repeat preserves profiles plus identity/federation/secret data byte-for-byte while removing only obsolete routing state.
  • Focused Rust/integration/smoke tests, cargo fmt --check, and cargo clippy pass with authoritative command evidence.
  • Do not globally install or restart the live daemon from the worker; leave the coordinated post-land gate to the operator.

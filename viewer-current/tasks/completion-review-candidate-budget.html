Description

Replace the overly broad task/requirements-wide strict review attempt counter with candidate-aware bounded review accounting.

Required behavior:

  • The same immutable manifest/candidate digest may not trigger duplicate semantic reviewer calls for the same reviewer identity/route; reuse its receipt.
  • A materially revised candidate with a new commit/manifest digest may receive review even when an earlier candidate was rejected, so an agent can address findings.
  • Preserve a separate configurable task-level spend/iteration ceiling. Reaching it transitions durably to NeedsReview/Waiting; it never fails source work and never requires a live Pi session.
  • Provider/evaluator infrastructure retries are accounted separately and must not consume semantic-revision budget.
  • Superseded receipts remain immutable and visible but cannot authorize the new candidate.

Validation

  • Same candidate submitted repeatedly invokes each reviewer at most once.
  • Revised candidate after rejection receives a new bounded review.
  • Task-level ceiling produces NeedsReview without source failure or additional model call.
  • Infrastructure unavailable does not consume semantic-revision allowance.
  • Restart preserves counters and receipt reuse.

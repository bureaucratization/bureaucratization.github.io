Description

Objective

Fix the supported completion/landing flow so operators never need git reset --hard gymnastics to satisfy WG's own guards. Preserve immutable receipts, candidate bytes, target fencing, and fail-closed behavior; add explicit recovery rather than weakening the invariants.

Implement the coherent fix for these interacting failures:

  1. WG-created .wg-worktrees/ must not dirty the root landing checkout. Do not edit user-owned .gitignore; use an appropriate WG-managed exclusion/location and make the finalizer distinguish WG runtime paths from user changes.
  2. When a pending landing's expected target is an ancestor of the current branch head, treat it as a recoverable stale-target condition, not immediate terminal failure. Do NOT merely waive the exact-ref check. Deterministically integrate/rebase as appropriate, re-run target-dependent validation, and issue renewed target-binding evidence before landing. Divergence, conflicts, changed required inputs, or failed validation still fail closed.
  3. Add a first-class, auditable state-machine path for Waiting(finalizer expectation stale) → reconciliation → refreshed validation/receipt → landing. It must work after the original worker has been released, preserve the selected candidate, create any required merge-resolution record itself, and expose a clear operator command/status when automation cannot proceed. Do not misuse retry/requeue/unclaim as if implementation failed.
  4. Error output must name the supported recovery action; no signpost may point to an impossible command.

Study the existing completion-object, merge-resolution, refresh-target, resume, publication, and landing code before choosing names. Reuse existing primitives where they are sound. Document the security argument for renewed evidence in code/tests.

Validation

  • Add focused tests proving WG-managed worktree creation leaves the root checkout landable without a committed .gitignore change.
  • Add tests for descendant-only target advance: candidate is retained, target-dependent evidence is renewed, validation runs, and landing succeeds without a live worker.
  • Add negative tests for divergence/conflict, user dirtiness, changed validation inputs, stale fence, and failed refreshed validation; all must remain fail-closed with candidate bytes intact.
  • Add a terminal-level smoke scenario reproducing the real human flow from candidate completion through self-created worktree state, target advance, worker release, reconciliation, and successful publication—without manual Git history rewrites. Register it in the grow-only smoke manifest with this task as owner.
  • Run the owned smoke scenario against the candidate binary plus focused Rust tests and cargo fmt --check.
  • Report exact changed files, validation output, invariant analysis, and residual risks.
